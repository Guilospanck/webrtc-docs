Uplink Congestion

When the sender is transmitting more media data than the network path can sustain.

💡 The key difference between uplink congestion and burst loss is that:
Congestion is gradual and persistent.

Burst loss is sudden and short.

Meaning:

  • Your outbound bitrate > available uplink capacity
  • Packets get delayed or dropped
  • RTT increases
  • Loss increases
  • Congestion controller reacts (reduces bitrate)

It has a pattern over time. It usually looks like:

  • RTT gradually increasing
  • remote-inbound-rtp.fractionLost rising
  • retransmittedBytesSent increasing (due to packet loss)
  • availableOutgoingBitrate (the network uplink capacity - kinda) decreasing
  • Eventually bitrate drops (congestion controller kicks in)

Uplink congestion timeline:

TimeRTTLossBitrateAvailable
t080ms1%1.5Mbps2.0Mbps
t1120ms3%1.6Mbps1.4Mbps
t2220ms8%1.7Mbps900kbps
t3450ms12%1.7Mbps600kbps
t4350ms4%600kbps700kbps

Notice:

  • RTT increases before collapse
  • Available bitrate (network uplink capacity - of some sorts) drops
  • Loss increases
  • Then the congestion controller slams bitrate down

Ways to detect it

A) RTT increasing

RTCRemoteInboundRtpStreamStats.roundTripTime
# or the fallback
RTCIceCandidatePairStats.currentRoundTripTime

# convert to ms
rttMs = roundTripTime * 1000

If it is steadily increasing, and it’s sustained, possibly uplink congestion.

B) Remote loss rising (LIMITED AVAILABILITY)

RTCRemoteInboundRtpStreamStats.fractionLost
# it provides a value that can be used to determine
# the fraction of packets lost for this SSRC in the last
# reporting interval.

Detecting it:

lossRate = fractionLost / 256

// if sustained > 5-10% AND
// combined with RTT rise
// => Classic uplink congestion

C) retransmittedBytesSent increasing

RTCOutboundRtpStreamStats.retransmittedBytesSent

# If there are packet being lost, this will increase

Detecting it:

retransmitBitrate = delta(retransmittedBytesSent) / deltaTime
retransmitRatio = retransmitBitrate / totalBitrate

# Example
if > 20-30% sustained => recovery overload

D) availableOutgoingBitrate dropping (LIMITED AVAILABILITY)

RTCIceCandidatePairStats.availableOutgoingBitrate

E) Bitrate collapses after spike

Congestion controllers (GCC) react by sharply reducing bitrate

If you see a drop in the bitrate after RTT/loss increase ⇒ congestion confirmed.

How to mitigate

💡 Important: do NOT trigger on a single sample. Use time windows. For example:

  • 3-5 consecutive samples

  • 5-15 second window

💡 You could also proactively downshift before loss happens, for example by checking the
totalBitrate > availableOutgoingBitrate

Fast downshift. Slow upshift. (same as burst loss).

Cap maxBitrate

async function reduceBitrate(sender: RTCRtpSender) {
  const p = sender.getParameters();

  for (const e of p.encodings ?? []) {
    if (typeof e.maxBitrate === "number") {
      e.maxBitrate = Math.floor(e.maxBitrate * 0.7);
    }
  }

  await sender.setParameters(p);
}

Reduce resolution

e.scaleResolutionDownBy *= 1.2;
// This works by reducing the encoder load and bitrate demand.

Reduce framerate

e.maxFramerate = 15;
// very effective for screen share

Slow recovery ramp

Do it slowly after stabilization

e.maxBitrate *= 1.05; // very slow increase

Production-grade uplink strategy

  1. Detect sustained congestion
  2. Immediate 30% bitrate reduction
  3. Disable highest layer if still unstable
  4. Wait 8-15s stable before ramp
  5. Ramp up slowly (5% per window)

Appendix

Detection logic. We look for:

  • Sustained RTT increase
  • Sustained loss
  • Sustained retransmit ratio
  • Outgoing bitrate > available capacity
interface UplinkSignals {
  rttMs?: number;
  packetLossRate?: number; // 0..1
  retransmitBitrateBps?: number;
  totalBitrateBps?: number;
  availableOutgoingBitrate?: number;
}

export function detectUplinkCongestion(s: UplinkSignals): boolean {
  const rttHigh = (s.rttMs ?? 0) > 300;
  const lossHigh = (s.packetLossRate ?? 0) > 0.08;

  const retransmitRatio =
    s.totalBitrateBps && s.retransmitBitrateBps
      ? s.retransmitBitrateBps / s.totalBitrateBps
      : 0;

  const highRecoveryLoad = retransmitRatio > 0.25;

  const overshooting =
    s.availableOutgoingBitrate &&
    s.totalBitrateBps &&
    s.totalBitrateBps > s.availableOutgoingBitrate * 1.2;

  return (
    (rttHigh && lossHigh) ||
    (highRecoveryLoad && rttHigh) ||
    overshooting
  );
}
