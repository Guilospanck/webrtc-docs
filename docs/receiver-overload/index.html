Receiver overload

💡 The receiving device cannot decode or render incoming video fast enough.

It’s a CPU/GPU bottleneck on the receiving side.

Receiver overload timeline:

TimeFPSLossRTTJitterFreeze
t0300%80ms8ms0
t1220%75ms7ms0
t2140%78ms9ms1
t3100%80ms8ms2

Notice:

  • Loss stable
  • RTT stable
  • Jitter stable
  • FPS collapsing
  • Freeze count increasing

Common causes

  1. Weak laptop CPU
  2. Mobile device thermal throttling
  3. 1080p or 4K video on weak device
  4. Too many simultaneous video streams
  5. AV1 decoding on unsupported hardware
  6. Software decoded instead of hardware decode
  7. Browser tab in background
  8. GPU under heavy load

Ways to detect it

Look at RTCInboundRtpStreamStats:

  • framesDecoded (limited availability)
  • freezeCount (if available)
  • totalProcessingDelay
  • jitter
  • packetsLost
  • bytesReceived

And optionally from the video element:

// HTML5 video element
video.getVideoPlaybackQuality()

A) FreezeCount increasing

freezeDelta = currentFreeze - previousFreeze

If this increases while:

  • packet loss low
  • RTT normal
  • Jitter low

Likely to be receiver overload.

B) FPS dropping

C) High processing delay

RTCInboundRtpStreamStats.totalProcessingDelay

# compute

avgProcessingDelay = totalProcessingDelay / framesDecoded

If decode/render delay per frame is high ⇒ overload.

D) Video element dropped frames

video.getVideoPlaybackQuality().droppedVideoFrames

If:

  • droppedVideoFrames increasing
  • and packet lost stable 0

Then it’s rendering overload.

How to mitigate

Unlike uplink congestion and encoder overload, you cannot adjust locally. You must, if possible, reduce what you’re receiving (SFU, simulcast) or signal the sender.

A) Switch to lower simulcast layer

B) Ask remote sender to reduce bitrate (P2P case)

The remote sender can reduce:

  • Bitrate
  • Framerate
  • Resolution

C) Limit decode complexity

  • Prefer H264 over AV1 on weak devices
  • Avoid too many active video tracks

Appendix

Detection logic.

The key rule is:

playback bad + network clean = receiver overload
interface ReceiverSignals {
  fps?: number
  freezeDelta?: number
  packetLossRate?: number
  jitterMs?: number
  rttMs?: number
}

function detectReceiverOverload(s: ReceiverSignals) {
  const lowFps = (s.fps ?? 30) < 15
  const freezing = (s.freezeDelta ?? 0) > 0
  const networkClean =
    (s.packetLossRate ?? 0) < 0.02 &&
    (s.jitterMs ?? 0) < 20 &&
    (s.rttMs ?? 0) < 200

  return (lowFps || freezing) && networkClean
}
