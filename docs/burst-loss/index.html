Burst loss

This is not a metric by itself, but something that you should infer from deltas between polls. It’s usually due to:

  • Wi-Fi interference: weak signal, microwave, roaming between Access Points (APs)
  • Cellular handoff: 4G ↔ 5G, tower change
  • Some local router overflowing stuff
  • CPU spikes: the sender unable to encode in time
  • Network drops

Typical burst loss timeline:

Timenackretransmitbitratejitterfreeze
t01low1.2mbps8ms0
t130high1.2mbps60ms0
t245very high900kbps80ms1
t32low600kbps12ms1

That spike between t1–t2 is burst loss.

Ways to detect it:

A) nackCount spike

This is a very strong signal for a burst loss.

RTCOutboundRtpStreamStats.nackCount

# This increments when the receiver
# tells you it missed packets.

Detecting it:

nackDelta > threshold within short window

# Example:
if (nackDelta > 15) {
  // likely burst
}

B) retransmittedBytesSent spike

RTCOutboundRtpStreamStats.retransmittedBytesSent

# If there are packet being lost, this will increase

Detecting it:

retransmitBitrate = delta(retransmittedBytesSent) / deltaTime

# Example
if (retransmitBitrate > totalBitrate * 0.3) {
// burst recovery in progress
// This indicates that RTX (retransmission) is working hard
// to recover from burst loss.
}

C) fractionLost spike (remote view) - LIMITED AVAILABILITY

RTCRemoteInboundRtpStreamStats.fractionLost
# it provides a value that can be used to determine
# the fraction of packets lost for this SSRC in the last
# reporting interval.

Detecting it:

lossRate = fractionLost / 256

// if lossRate jumps from 0.01 -> 0.25 -> 0.02
// within 1-2 seconds, that's a burst

D) jitter spike

RTCInboundRtpStreamStats.jitter // seconds

# if jitter suddenly increases
# Example
# jitterMs > 40
# combined with nack spike and retransmit spike
# Then VERY LIKELY burst loss

E) Frame freezes (video)

freezeCount delta > 0

# if this increases right after nack spike, then it's 
# classic burst effect

What to do when burst loss is detected

Fast downshift. Slow upshift.

Temporary bitrate reduction

const params = sender.getParameters();

for (const enc of params.encodings ?? []) {
  if (typeof enc.maxBitrate === "number") {
    enc.maxBitrate = Math.floor(enc.maxBitrate * 0.75);
  }
}

await sender.setParameters(params);

Delay recovery

Do NOT immediately increase bitrate again. Wait for:

  • RTT stable
  • nackDelta low
  • retransmit ratio < 5%
  • stable for 5-10 seconds

Then slowly increase:

enc.maxBitrate *= 1.1

Optional: increase jitter buffer on the receiver side

// if supported (LIMITED AVAILABILITY)
receiver.jitterBufferTarget = 200; // ms

Appendix

Simple burst loss detector:

interface BurstDetectionResult {
  detected: boolean;
  severity: "mild" | "moderate" | "severe";
}

function detectBurstLoss(metrics: {
  nackDelta?: number;
  retransmitBitrateBps?: number;
  totalBitrateBps?: number;
  packetLossRate?: number;
  jitterMs?: number;
}): BurstDetectionResult {

  const {
    nackDelta = 0,
    retransmitBitrateBps = 0,
    totalBitrateBps = 1,
    packetLossRate = 0,
    jitterMs = 0,
  } = metrics;

  const retransmitRatio = retransmitBitrateBps / totalBitrateBps;

  // Strong burst indicators
  const severe =
    nackDelta > 25 ||
    retransmitRatio > 0.5 ||
    packetLossRate > 0.2;

  const moderate =
    nackDelta > 10 ||
    retransmitRatio > 0.3 ||
    packetLossRate > 0.1 ||
    jitterMs > 40;

  if (severe) return { detected: true, severity: "severe" };
  if (moderate) return { detected: true, severity: "moderate" };

  return { detected: false, severity: "mild" };
}
